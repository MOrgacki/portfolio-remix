# Contract: Language Runtime

Covers FR-007–FR-011, FR-026 and the spec's language edge cases.

## Storage

| Item | Value |
|---|---|
| Mechanism | `window.localStorage` (no cookies) |
| Key | `portfolio.lang` |
| Values | `"en"` \| `"pl"`; anything else is treated as unset |
| Written | Only when the visitor presses the language button |

## Resolution order (inline script in `<head>`, runs before first paint)

1. Stored value, if valid.
2. Browser locale: first of `navigator.languages` (or `navigator.language`) starting with `pl` →
   `"pl"`.
3. `"en"`.

Storage access is wrapped in try/catch; failure falls through to step 2.

## DOM contract

| Element / attribute | Meaning |
|---|---|
| `<html data-lang="en\|pl" lang="en\|pl">` | Active language; set by the head script and the toggle |
| `<span lang="en">…</span><span lang="pl">…</span>` | Output of `<T k="key"/>`; CSS shows only the active one |
| `data-i18n-alt-en` / `data-i18n-alt-pl` (likewise `-aria-label-`, `-placeholder-`, `-title-`) | Attribute values swapped by the language script |
| `<meta name="i18n-title-pl" content="…">` | Polish tab title; English is the static `<title>` |
| `button[data-lang-toggle]` | The language button; `aria-label` names the target language; `aria-pressed` not used |

Default CSS (no JS): Polish spans hidden, English visible.

## Events

- On toggle, the script dispatches `window` event `langchange` with `detail: { lang }`.
  The projects script listens to re-run search against the newly active language and to update
  an open pop-up.

## Build-time guarantees

- `src/i18n/en.json` and `src/i18n/pl.json` have identical key sets and no empty values;
  `npm run check:i18n` exits non-zero otherwise and runs before every build (FR-011).
- `<T k>` accepts only keys of `en.json` (type error otherwise).
- Every Localized field in project data has non-empty `en` and `pl` (schema validation).
